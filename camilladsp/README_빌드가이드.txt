체인 (음악):
  TIDAL(독점 모드, 곡 네이티브 레이트) → VAC "Line 1" (정식판, 무변환 통과)
  → CamillaDSP v4.1.3 (WASAPI 독점 캡처 S24/S32, 무필터·무리샘플러 패스스루)
  → MOTU M Series ASIO (버퍼 512) → M4 → (앰프/스피커·헤드폰)
체인 (일상/게임):
  음악 정지 60초 후 Camilla가 M4 반납 → M4 공유 + EqAPO 프리셋으로 자동 복귀

핵심 성질:
  - 레이트 자동 추종 (44.1/48/88.2/96/176.4/192k) — 곡이 바뀌면 체인이 재조립됨
  - 정합 시 VAC 무SRC + 캄일라 무리샘플러 → 설계상 직결과 비트 동일
  - 전환 총 시간 ~2.5초 (감지→일시정지→재조립→1.2초 대기→재개)
  - 곡 내용 유실 없음 (SMTC 일시정지 후 멈춘 지점부터 재개)
    * 잔여 ~0.1초 앞부분 페이드는 TIDAL 자체 동작 = 바닥값

■ 구성 요소
────────────────────────────────────────────────────────────────
① Virtual Audio Cable 4.71 (뮤지첸코) — Line 1 케이블 1개
② CamillaDSP v4.1.3 asio 빌드 — C:\CamillaDSP\camilladsp.exe
③ supervisor.py — 자동화 전부 (감시·오라클·전환·자가복구)
④ Python 패키지: sounddevice numpy websocket-client winsdk

■ 고정 설정 (재설치 시 이대로)
  [MOTU 패널]  Buffer 512 / lowest latency offsets 끔
               ("Sync Windows sample rate to device"는 ASIO 구동이라 무해)
  [VAC 케이블] SR 22050..192000 / BPS 8..32 / NC 1..2
               Stream fmt limit = "Cable range"
               Volume control 끔 / Channel mixing 끔 (투명성)
  [TIDAL]      출력 = Line 1 (Virtual Audio Cable) + ★독점 모드 켬★
               (장치 재등록 후엔 독점이 풀릴 수 있음 — 반드시 재확인!)
  [supervisor] wait_pipeline_ready timeout=1.2s (청취 이분탐색 확정값)
               CAPTURE_FORMATS = S24 → S32 → S16 자동 폴백
               (실측: 88.2k까지 S24, 192k는 S32로 열림 — S32도 무손실)

■ 동작 원리 — 이중 오라클
  1) TIDAL 로그 오라클: %APPDATA%\TIDAL\Logs\player.log 의
     "Decoder got ... sampleRate: N" 라인을 증분 tail로 읽음 (곡의 진실,
     단 플러시가 수십 초 늦을 수 있음)
  2) 케이블 실측 오라클: VAC 제어판 리스트뷰의 Current format(sub9)과
     Pb stms(sub11)를 원격 LVM_GETITEMTEXT로 직접 읽음 (실시간, 즉답)
     → 제어판이 닫혀 있으면 자동 실행함
  판정: 실측이 로그보다 우선. 전환 감지 시 현 체인 신호가 계속 살아있으면
  스테일 라인으로 보고 무시(가드). 렌더 스트림 0개면 프로브 자체를 안 함.
  ※ 실측 레이트 ≠ 곡 레이트로 어긋나면 → TIDAL 독점 모드가 풀린 것 (공유
     모드 = 윈도우 엔진 SRC 개입 = 음질 열화). 독점 다시 켤 것.

■ 전환 시퀀스 (레이트 변경 감지 시)
  감지 → SMTC 명시적 일시정지(상태 PAUSED 확인까지 재명령; 곡 시작 직후
  CHANGING 창에서 명령이 무시되는 것 실측 대응) → 구 카밀라 종료 →
  새 레이트로 기동(전환 모드: 생존 즉시 합격) → 1.2초 대기(캡처+ASIO
  소비 준비; 일시정지 중엔 버퍼가 원천적으로 안 차므로 고정 대기가 정답)
  → SMTC 명시적 재생 → 0.8초 후 상태 검증, PAUSED면 재명령(최대 3회)
  ※ 미디어 키 토글은 폴백 전용 (상태를 모르는 토글이라 유실·반전 위험)

■ 리샘플러 관련 (중요 결정 사항)
  현재 config_template.yml 은 리샘플러 없음 = 최투명 (청취로 선택함).
  트레이드오프: VAC(시스템 클럭)와 MOTU(하드웨어 클럭)의 미세 드리프트가
  보정되지 않음 → 같은 레이트로 수 시간 연속 재생 시 드문 틱 1회 가능.
  단, 곡 전환/일시정지마다 체인이 재기동돼 버퍼가 리셋되므로 실사용 영향 작음.
  틱이 거슬리면: config_template_drift_backup.yml (AsyncSinc Balanced)로
  복원하거나 profile을 Accurate로 바꿔 쓸 것.

■ 모비우스 음감 모드 확정 사실 (2026-08-27 새벽 실측)
  · 모비우스 독점(하이레즈 2ch)은 96kHz 단일 레이트만 수락 (비트폭은 16/24/32 자유)
    → 캡처는 곡 네이티브(케이블 무변환), 카밀라 AsyncSinc Accurate로 96k 변환이 최선
  · VAC은 레이트 불일치 시 내부 SRC로 신호를 살려줌 → "무신호=불일치" 가정 무효.
    이 때문에 신호 기반 스테일 가드는 진짜 전환을 영구 기각하는 교착을 만들어 폐기함
    (현재: 디코더 오라클/케이블 실측 항상 신뢰. 유령 라인 헛전환은 드물고 자가 복구)
  · 캡처 스트림이 먼저 열리면 케이블 포맷이 캡처 레이트로 고정됨 (Cable range 특성)

■ 트러블슈팅 (전부 오늘 밤 실제로 겪고 해결한 것들)
  · 소리가 "필터 낀 듯" 답답함 → ①TIDAL 독점 모드 풀림(케이블 실측 레이트가
    곡과 다르면 확정) ②과거: AsyncSinc Balanced 리샘플러 착색 → 제거함
  · 곡이 44.1인데 케이블이 48k → 공유 모드 (독점 다시 켜기)
  · S16으로 떨어짐 → 일시정지 중 프로브가 ws_dead 예외로 무검증 통과하던
    버그였음(수정됨: ws 생존 이력 있으면 무검증 합격 금지). 재시작하면 S24 복귀
  · 전환 후 멈춘 채로 있음 → SMTC 도입 전 토글 유실 증상. 현재는 상태 검증
    + 재명령으로 자가복구 (로그: "재개 미반영 — 재생 명령 재전송")
  · 프로브가 수십 초 폭주 → TIDAL 로그 플러시 지연. 케이블 실측 오라클
    도입으로 해소 (로그: "케이블 실측: NNNNHz")
  · 전환 직후 팝/앞부분 삼킴 → 재개가 파이프라인 준비보다 빨랐던 것.
    1.2초 대기 + MOTU 버퍼 512로 해소
  · VAC 케이블 설정 변경이 안 됨 → 스트림이 0이어야 함. TIDAL은 일시정지
    중에도 독점 스트림을 물고 있으므로 TIDAL 출력을 잠깐 다른 장치로 변경
  · 케이블 설정 변경 후 TIDAL이 소리를 안 밈 → 장치 참조 끊김. TIDAL에서
    출력 장치 재선택 (+독점 모드 재확인)
  · 192k에서 S24 캡처 실패 → 정상 (S32로 자동 폴백, 무손실)
  · 수퍼바이저가 갑자기 아무것도 안 함(전환 무시, 로그 정지) → 콘솔 창에서
    텍스트를 드래그/선택하면 프로세스가 통째로 얼어붙음(quick-edit 프리즈).
    콘솔 클릭 후 Esc나 아무 키로 선택 해제하면 즉시 복구. 부팅 자동시작은
    숨김 실행이라 이 문제 자체가 없음 (2026-08-27 04:01~13 실제 사례)
  · 하이레즈가 48k/16으로 뭉개짐 → TIDAL 독점 풀림/공유 폴백. 케이블 실측이
    곡 레이트와 다르면 확정. TIDAL은 X 눌러도 트레이에 살아있으므로
    설정 변경 후엔 트레이까지 완전 종료 후 재실행할 것

■ A/B 비교할 때 주의 (오늘 밤의 교훈)
  · 같은 DAC끼리 비교할 것 (체인 vs M4 직결). 노트북 직결과의 차이는
    DAC/앰프/출력임피던스/음향효과 차이지 체인의 결함이 아님
    (특히 멀티 BA 이어폰은 출력 임피던스에 따라 음색이 실제로 변함)
  · TIDAL은 출력 장치별로 볼륨을 따로 기억함 — 양쪽 100% 확인
  · 비교 전 독점 모드 여부부터 확인 (이거 하나로 "색감"이 확 바뀜)
